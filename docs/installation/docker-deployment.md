# Docker Deployment (Standalone Container)

This guide covers building and running the sdkwork-cloudrouter **standalone
container image** (`runtimeTarget = "container"`, `deploymentProfile =
"standalone"`). The image is a single application unit: it serves the portal
SPA, the application public ingress (OpenAI-compatible `/v1/*`, app/admin API
surfaces, `/healthz`, `/readyz`) and runs database initialization on startup.

For the cloud orchestration layout (edge + gateway + admin/app API pods), see
`deployments/kubernetes/`. For the host package layout, see
[TECH-deployment-modes.md](../architecture/tech/TECH-deployment-modes.md).

## 1. Dependency inventory

### 1.1 Inside the image (release artifacts)

| Item | Path in image | Source | Notes |
| --- | --- | --- | --- |
| Standalone gateway binary | `/opt/sdkwork/router/bin/cloudrouter` | `target/release/sdkwork-api-cloudrouter-standalone-gateway` | Main process; serves portal static + APIs on `0.0.0.0:3900` |
| Installer binary | `/opt/sdkwork/router/bin/cloudrouterctl` | `target/release/cloudrouterctl` | `ensure` / `refresh-catalog --force` on startup |
| Entrypoint | `/opt/sdkwork/router/container/entrypoint` | generated by install package builder | `ensure` → `refresh-catalog` → `exec cloudrouter` |
| Portal SPA (dist) | `/opt/sdkwork/router/portal/dist` | `apps/sdkwork-cloudrouter-pc/dist` | gateway-static delivery: `/` mount + `/index.html` SPA fallback |
| SDK archives | `/opt/sdkwork/router/portal/dist/sdk-archives` | same dist tree | published artifact requirement (DEPLOYMENT_SPEC §5.4) |
| Config example | `/opt/sdkwork/router/config/cloudrouter.toml.example` | generated | examples only; runtime config is mounted |
| Install manifest | `/opt/sdkwork/router/install-manifest.json` | generated | release evidence |
| Install guide | `/opt/sdkwork/router/INSTALL.md` | generated | release evidence |
| Env template | `/opt/sdkwork/router/.env.release.example` | repository root | reference only, never loaded |
| App identity | `/opt/sdkwork/router/sdkwork.app.config.json` | repository root | IAM tenant provisioning (`SDKWORK_APP_ROOT`) |
| Federated DB modules | `/opt/sdkwork/router/database-modules/<repo>/database` | sibling repos (`sdkwork-models`, `sdkwork-cloudrouter`, `sdkwork-payment`, `sdkwork-account`, `sdkwork-agents`, `sdkwork-appbase`, `sdkwork-community`, `sdkwork-drive`, `sdkwork-iam`, `sdkwork-inventory`, `sdkwork-invoice`, `sdkwork-log`, `sdkwork-membership`, `sdkwork-order`, `sdkwork-partner`, `sdkwork-promotion`, `sdkwork-aiot`, `sdkwork-image`, `sdkwork-web-framework`) | manifests + migrations + seeds; each host resolves its module via `SDKWORK_<NAME>_APP_ROOT` |
| IAM registry data | `/opt/sdkwork/router/database-modules/sdkwork-iam/iam` | `sdkwork-iam/iam` | registry config + module manifests |
| Models catalog | `/opt/sdkwork/router/data/sdkwork-models` | `sdkwork-models/{sdkwork-models.json,models,overlays}` | `SDKWORK_MODELS_CATALOG_ROOT` |
| Runtime libs | system | `debian:bookworm-slim` + `libssl3` + `ca-certificates` | gateway TLS (PostgreSQL/HTTPS) |

The committed `Dockerfile` at the repository root is the build input for
`pnpm build:container`; it is equivalent to the `container/Containerfile`
generated inside install packages by
`scripts/build-cloud-router-install-package.mjs`.

### 1.2 External services (never baked into the image)

| Dependency | Version | Compose service | Notes |
| --- | --- | --- | --- |
| PostgreSQL | 16 | `postgres` | Required (`requiresExternalDatabase`). Connection via `SDKWORK_DATABASE_URL` or `SDKWORK_DATABASE_*` env. |
| Redis | 7 | `redis` | Required by default (`[redis].enabled = true`). Connection via `SDKWORK_CLOUDROUTER_REDIS_*` env. |

### 1.3 Mounted runtime layout (RUNTIME_DIRECTORY_SPEC §4.5)

| Mount point | Kind | Content |
| --- | --- | --- |
| `/etc/sdkwork/router/cloudrouter.toml` | read-only config | runtime TOML; overridable with `SDKWORK_CLOUDROUTER_CONFIG_FILE` |
| `/run/secrets/sdkwork/router/*` | read-only secrets | e.g. `postgres-password`, `redis-password` |
| `/var/lib/sdkwork/router` | writable data volume | durable app data |
| `/var/cache/sdkwork/router` | writable | cache |
| stdout/stderr | logs | container logs, no log files |

Secrets are injected through mounts or orchestrator secret managers; the image
contains examples only and no production secrets, database state, or
`.env.release` files.

## 2. Port plan (never collides with `pnpm dev`)

`pnpm dev` listens on **3900** (Rust gateway) and **3901** (Vite dev server).
The container listens on **3900 inside its own network namespace** (the spec
default application public ingress) and is published on the host as **3903**,
which is free of every workspace port.

| Host port | Container port | Owner |
| --- | --- | --- |
| 3903 | 3900 | cloudrouter container (compose default) |
| — (compose network only) | 5432 | postgres |
| — (compose network only) | 6379 | redis |

Ports deliberately avoided on the host: 3900 (dev gateway), 3901 (dev vite),
3902 (client-only remote ingress), 18080–18082 (distributed debug API
surfaces), 5432/15432 (dev/test PostgreSQL), 6379 (dev Redis), 80/443 (nginx),
41000–41999 (dev smoke range).

## 3. Build

Prerequisites: Linux or WSL host (Linux binaries), Docker daemon running, and
the release build products:

```bash
cargo build --release -p sdkwork-api-cloudrouter-standalone-gateway -p sdkwork-cloudrouter-installer
pnpm --dir apps/sdkwork-cloudrouter-pc build   # if dist/ is stale
```

Then build the image:

```bash
pnpm build:container            # docker build -f Dockerfile -t cloudrouter:local
pnpm build:container:check      # validate the plan without building
```

The build assembles `dist/install-package-staging/`, produces the container
install package (`dist/install-packages/cloudrouter-linux-x64-container-<version>.tar.gz`),
unpacks it into `dist/container-image-build/`, runs `docker build`, and records
the immutable image evidence in `dist/container-image.json`:

```json
{
  "schemaVersion": "2026-08-07.container-image.v1",
  "packageId": "linux-x64-container",
  "version": "0.3.0",
  "imageTag": "cloudrouter:local",
  "packageArchiveSha256": "...",
  "repoDigest": null,
  "imageId": "sha256:...",
  "buildDate": "..."
}
```

The `imageId`/`repoDigest` are the immutable image digests; mutable tags are
convenience labels, not release identity (RELEASE_SPEC §4.1).

## 4. Run

### 4.1 docker compose (recommended, bundled PostgreSQL + Redis)

```bash
pnpm build:container
docker compose up -d
```

Services: `cloudrouter` (host port `3903:3900`), `postgres`, `redis` (compose
network only). Override credentials with a `.env` file next to
`docker-compose.yml` (`CLOUDROUTER_POSTGRES_DB`, `CLOUDROUTER_POSTGRES_USER`,
`CLOUDROUTER_POSTGRES_PASSWORD`).

### 4.2 docker run (external PostgreSQL + Redis)

```bash
mkdir -p secrets
printf '%s' '<postgres-password>' > secrets/postgres-password
printf '%s' '<redis-password>'   > secrets/redis-password

docker run --rm -d --name cloudrouter \
  -p 3903:3900 \
  -v "$PWD/secrets/postgres-password:/run/secrets/sdkwork/router/postgres-password:ro" \
  -v "$PWD/secrets/redis-password:/run/secrets/sdkwork/router/redis-password:ro" \
  -v cloudrouter-data:/var/lib/sdkwork/router \
  -e SDKWORK_DATABASE_URL='postgresql://<user>:<password>@<host>:5432/<db>' \
  -e SDKWORK_CLOUDROUTER_REDIS_ENABLED=true \
  -e SDKWORK_CLOUDROUTER_REDIS_HOST=<host> \
  -e SDKWORK_CLOUDROUTER_REDIS_PORT=6379 \
  -e SDKWORK_CLOUDROUTER_API_KEY_PEPPER='<random>; use -_FILE variant in production' \
  -e SDKWORK_CLOUDROUTER_UPSTREAM_CREDENTIAL_KEY_RING='{"activeKeyId":"k1","activeKey":"<32+ bytes>","fingerprintKey":"<32+ bytes>","decryptionKeys":[]}' \
  -e SDKWORK_CLOUDROUTER_INTERNAL_GATEWAY_SIGNING_SECRET='<random>' \
  -e SDKWORK_CLOUDROUTER_TRUSTED_SUBJECT_SECRET='<random>' \
  -e SDKWORK_CLOUDROUTER_APP_SESSION_SECRET='<random>' \
  -e SDKWORK_CLOUDROUTER_PAYMENT_WEBHOOK_SECRET='<random>' \
  -e SDKWORK_PAYMENT_CREDENTIAL_MASTER_KEY_FILE='/var/lib/sdkwork/router/secrets/payment-credential-master.key' \
  cloudrouter:local
```

Use `-p <host-port>:3900` with any free host port; 3903 is the workspace
default. In production, inject secrets via `*_FILE` variants (e.g.
`SDKWORK_CLOUDROUTER_API_KEY_PEPPER_FILE`) backed by mounted secret files
(`/run/secrets/sdkwork/router/*`), and pre-provision the payment master key
file on the data volume.

## 5. Verify

```bash
curl -fsS http://127.0.0.1:3903/healthz      # liveness
curl -fsS http://127.0.0.1:3903/readyz       # readiness
curl -fsS http://127.0.0.1:3903/openapi.json # API contract
curl -fsS http://127.0.0.1:3903/             # SPA shell
docker compose ps                            # all services healthy
ss -tlnp | grep -E '390[0-3]'                # host: only 3903 served by the container
```

## 6. Spec compliance notes

- Script naming: `build:container` follows PNPM_SCRIPT_SPEC runtime-target
  naming; `docker:*` public script names are forbidden.
- Identity: `runtimeTarget = "container"`, `deploymentProfile = "standalone"`;
  the image declares `SDKWORK_CLOUDROUTER_DEPLOYMENT_PROFILE` /
  `SDKWORK_CLOUDROUTER_RUNTIME_TARGET` env defaults (DEPLOYMENT_SPEC §5.2).
- Single HTTP bind: the application public ingress is the only listener on the
  application plane (APP_RUNTIME_TOPOLOGY_SPEC §8); bind values come from env,
  never hard-coded ports in source.
- Secrets and configuration are mounted; durable data lives on volumes; the
  image contains examples only (DEPLOYMENT_SPEC §5.4, ENVIRONMENT_SPEC §10.6,
  RUNTIME_DIRECTORY_SPEC §4.5).
- The build records immutable image evidence (digest, package sha256, build
  date) instead of relying on mutable tags (RELEASE_SPEC §4, §5).

# Crate Rename Plan

## Scope

This plan tracks SDKWork naming-spec compliance for Rust crates in `sdkwork-clawrouter`.
The authoritative rule is `sdkwork-specs/NAMING_SPEC.md` section 4.3: the suffix
`sdkwork-<application-code>-core` is forbidden because `core` does not describe a
responsibility. Crates must be named after their owning responsibility.

## Completed Renames (H-12 Critical Batch)

### 1. `sdkwork-claw-core` → `sdkwork-claw-health`

- **Directory**: `crates/sdkwork-claw-core/` → `crates/sdkwork-claw-health/`
- **Reason**: The crate only exports `DatabaseHealth` and `HealthResponse` for the
  health-endpoint surface. `health` is the accurate responsibility name.
- **Updated references**: root `Cargo.toml` (members, default-members,
  workspace.dependencies), `crates/sdkwork-claw-http/Cargo.toml` and its
  `src/router.rs`/`src/health.rs` `use` statements,
  `services/sdkwork-clawrouter-router-service/Cargo.toml`,
  `.github/CODEOWNERS`, `tools/rust_backend_architecture_guardian.py`,
  `tests/test_rust_backend_architecture_guardian.py`,
  `tests/test_schema_quality_gate.py`, and the crate's own
  `Cargo.toml`/`README.md`/`specs/`.

### 2. `sdkwork-claw-provider-adapter-core` → `sdkwork-claw-provider-adapter`

- **Directory**: `crates/sdkwork-claw-provider-adapter-core/` → `crates/sdkwork-claw-provider-adapter/`
- **Reason**: Dropping the forbidden `-core` suffix. The crate owns the
  `ProviderAdapter`/`EndpointAdapter` traits and invocation context types.
- **Service conflict resolution**: The binary service at
  `services/sdkwork-claw-provider-adapter/` previously held the package name
  `sdkwork-claw-provider-adapter`. To free the name for the library crate, the
  service package was renamed to `sdkwork-claw-provider-adapter-host`. The
  service directory and binary name (`claw-provider-adapter`) are unchanged so
  deployment and CI references remain stable.
- **Updated references**: root `Cargo.toml` (members, default-members,
  workspace.dependencies for both the crate alias and the service alias),
  `crates/sdkwork-claw-provider-adapter-http/Cargo.toml`,
  `crates/provider-adapters/alicloud/Cargo.toml`,
  `crates/provider-adapters/tencent-cloud/Cargo.toml`,
  `services/sdkwork-claw-provider-adapter/Cargo.toml` (package name + dependency),
  all `use sdkwork_claw_provider_adapter_core` → `use sdkwork_claw_provider_adapter`
  in Rust sources, `.github/CODEOWNERS`,
  `tests/test_provider_adapter_architecture_standard.py`, and the crate's own
  `Cargo.toml`/`README.md`/`specs/`.

## Verification

- `cargo test -p sdkwork-claw-health -p sdkwork-claw-provider-adapter -p
  sdkwork-claw-provider-adapter-http -p sdkwork-provider-adapter-tencent-cloud`

- Pre-existing compilation failures in `sdkwork-provider-adapter-alicloud`

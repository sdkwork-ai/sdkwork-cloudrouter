## 目标

让 clawrouter 的 Rust 后端通过 **api-assembly** 组合 `sdkwork-api-agents-assembly` 的 app-api 贡献，直接服务 `/app/v3/api/ai/*`（agents / projects / sessions / workspaces 等），消除 404。前端链路（`clawrouter-pc` → `@sdkwork/agents-app-sdk` → 同源 `/app/v3/api` → Vite 代理 → 网关 :3900）保持不变。

## 依据

- 报错链路：`clawrouter-pc`(:3901) 嵌入 `@sdkwork/agents-pc/workbench`，SDK 请求 `/app/v3/api/ai/agents/agent.chat.default`、`/ai/projects` → 代理到 clawrouter standalone-gateway(:3900) → 后端未装配 agents app-api 路由 → 404。
- `API_ASSEMBLY_SPEC.md` §3：消费方网关必须通过**依赖方 assembly 的公开贡献入口**组合依赖表面（禁止直连依赖路由 crate）。clawrouter 已有同类先例：`commerce_runtime.rs` 组合 `sdkwork_api_order_assembly::assemble_app_api_contribution_with_pool(...)`。
- `sdkwork-agents` 已提供规范入口 `sdkwork_api_agents_assembly::assemble_app_api_contribution()`（内含路由 + 清单 + 注入器 + readiness），其 app-api 路由路径 `/app/v3/api/ai/*` 与 SDK 完全一致，与 clawrouter 自有 `/app/v3/api/ai/*`（usage/logs、routing、generations、dashboard 等）无冲突。
- agents DB 适配器按 `SDKWORK_AGENTS_*` → 回退 `SDKWORK_DATABASE_URL` 解析（commerce 的 `materialize_federated_database_env_from_config` 已设置后者）。

## 改动（全部在 sdkwork-clawrouter 仓库）

1. **根 `Cargo.toml`**（`[workspace.dependencies]`）新增：
   - `sdkwork-api-agents-assembly = { package = "sdkwork-api-agents-assembly", path = "../sdkwork-agents/crates/sdkwork-api-agents-assembly" }`
   - `sdkwork-agents-database-host = { package = "sdkwork-agents-database-host", path = "../sdkwork-agents/crates/sdkwork-agents-database-host" }`

2. **`crates/sdkwork-routes-clawrouter-app-api/Cargo.toml`**：添加上述两个 workspace 依赖（镜像 order-assembly 的依赖声明方式）。

3. **新文件 `crates/sdkwork-routes-clawrouter-app-api/src/agents_runtime.rs`**（镜像 `commerce_runtime.rs` 模式）：
   - `wire_agents_app_router()`：调用 `sdkwork_api_agents_assembly::assemble_app_api_contribution().await`（内部构建 `AgentHttpState`、执行 agents 数据库生命周期）并返回 `contribution.router`。
   - `merge_federated_agents_app_router(router, subject_boundary_config)`：经 `sdkwork_claw_http::merge_federated_app_capability_router_with_optional_auth` 合并。
   - **仅 PostgreSQL 引擎启用**（agents 状态构建要求 Postgres；SQLite/desktop 档案跳过并记录日志）。
   - 契约测试（镜像 commerce_runtime 测试风格）：断言使用 `sdkwork_api_agents_assembly::assemble_app_api_contribution` 贡献入口、未直连 `sdkwork-routes-agents-app-api` 依赖路由 crate、存在 Postgres 门控。

4. **`crates/sdkwork-routes-clawrouter-app-api/src/routes.rs`**：在 `finalize_product_router_with_federated_capabilities` 中（invoice/commerce 合并之后）接入 `merge_federated_agents_app_router`。

5. **`crates/sdkwork-claw-http/src/federated_database_env.rs`**：`FEDERATED_CAPABILITY_REPO_DIRS` 增加 `("AGENTS", "sdkwork-agents")`，物化 `SDKWORK_AGENTS_APP_ROOT`（与其他联邦能力一致，保证 agents 数据库模块 app_root 解析）。

不改：前端 `sdk-clients.ts`（同源 `/app/v3/api` 装配已符合规范）、agents 仓库、生成 SDK、UI 视觉。

## 验证

1. `cargo check -p sdkwork-routes-clawrouter-app-api` 及新增模块单测（`cargo test -p sdkwork-routes-clawrouter-app-api agents_runtime`）。
2. 启动 standalone gateway（Postgres），curl 验证 `GET /app/v3/api/ai/projects?page=1&page_size=50`、`GET /app/v3/api/ai/agents/agent.chat.default` 不再 404（需 portal 会话；如无会话则以 dev 环境验证路由装配与错误形态）。
3. 浏览器复现原 404 场景确认消失。

## 风险与提示

- 跨仓库 Cargo 依赖引入 agents 内核（sdkwork-agent-server / agent-kernel 等）与 `Cargo.lock` 更新；若编译期版本冲突，在实施中解决并报告。
- agents 数据库迁移会在 clawrouter 共享 Postgres 中执行（新增 agents 业务表）——首次启动网关时自动迁移。
- agents 路由受 IAM 门控，依赖 clawrouter web framework 提供的会话上下文（与现有联邦能力一致）。

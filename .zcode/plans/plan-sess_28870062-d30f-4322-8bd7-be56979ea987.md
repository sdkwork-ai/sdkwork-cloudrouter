# 营销中心优惠券优化实施计划

## 背景与现状

- 优惠券后端（offer/stock/批次/券码/领取/核销）全部在兄弟仓库 `E:\sdkwork-space\sdkwork-promotion`，经 `@sdkwork/promotion-backend-sdk` 暴露给 clawrouter admin 前端（13 个端点已存在）。
- clawrouter 前端 `sdkwork-clawrouter-pc-admin-marketing` 目前是 7 个只读占位列表，**列字段与真实后端 DTO 不匹配**（`code_mode`/`activation_status` 等字段后端不存在），页面不可用。
- 已确认需求：领取时从批次码池发码（预生成池模式）、允许改 sdkwork-promotion、优惠券支持金额券 + 订阅权益券两种类型。

## 后端改造（sdkwork-promotion 仓库）

### 1. 数据库迁移 `database/migrations/postgres/0003_*`
- `promotion_coupon_stock` 增加 `code_issue_mode VARCHAR(16) NOT NULL DEFAULT 'REALTIME'`（'REALTIME' | 'BATCH'），标记券码生成方式；更新 `metadata.json`。
- 无其他表结构变更（批次/券码表已存在，`promotion_user_coupon.code_id` 已存在）。

### 2. 领取逻辑改造（预生成池发码）
`crates/sdkwork-commerce-promotion-repository-sqlx`（postgres + sqlite 双实现，`postgres_promotion.rs` / `sqlite_promotion.rs` 的 `claim_promotion_user_coupon`）：
- 按 stock 的 `code_issue_mode` 分支：
  - **REALTIME**（默认，当前行为）：`coupon_code = CL-{requestNo}`，`code_id = NULL`。
  - **BATCH**：从该 stock 关联的 READY 批次池中取最早可用码（`SELECT ... FOR UPDATE` 守卫 `claimed_quantity < max_claims`），`UPDATE promotion_code SET claimed_quantity+1, status=CLAIMED`（max_claims=1 时），`user_coupon.code_id/coupon_code` 写入池码；库存扣减逻辑沿用现有 CAS 守卫。
- 顺手修复已发现的 bug：领取侧 `stock_type` 判断用 `'unlimited'` 小写、后台存 `'UNLIMITED'` 大写导致 unlimited 库存仍被扣减 → 统一为不区分大小写。

### 3. 管理端点能力补齐
- `operations.rs`：`ListParams` 增加可选 `code_batch_id`、`stock_id`；`list_codes` 支持按批次过滤（批次券码页必需）、`list_code_batches` 支持按 stock 过滤；`CouponStockRequest` 增加 `code_issue_mode`。
- `backend_admin.rs`：`PromotionCouponStockItem/Input` 增加 `code_issue_mode` + 枚举校验；`PromotionAdminListQuery` 增加过滤字段。
- `promotion_admin.rs` / `promotion_admin_management.rs`：CODE 列表 SQL 增加 `code_batch_id` 条件、BATCH 列表 SQL 增加 `stock_id` 条件（Postgres `$n` + SQLite `?n` 双写）、create_stock 写入 `code_issue_mode`。
- OpenAPI `apis/backend-api/promotion/sdkwork-promotion-backend-api.openapi.json`：codes.list 加 `code_batch_id` 参数、code_batches.list 加 `stock_id` 参数、couponStocks.create 请求体/响应加 `code_issue_mode`。
- 重新生成 SDK：`pnpm sdk:generate`（sdkwork-promotion 根），校验 `pnpm sdk:check`。
- 测试：repository 层 sqlite 内存库测试（池码发放流程：建批次→领取→池码被占用、池空拒绝）、operations 单元测试。

## 前端改造（clawrouter 仓库）

### 4. 路由与菜单
- `clawRouterAdminHostMount.tsx`：marketing 路由 path 改为 `marketing/:sectionId?/:batchId?`（支持批次券码详情页）。
- `adminModuleRegistry.ts` 营销菜单重构（8 项，4 组）：
  - 活动设计：优惠券管理（offers）、优惠券库存（stocks）
  - 券码管理：**券码批次（新增菜单项）**、券码查询（原"营销兑换码"入口保留，满足"统一券码查询页入菜单"）
  - 用户生命周期：领取记录（userCoupons）、券码使用历史（discountApplications）
  - 台账与增长：优惠券台账（ledger）、邀请分析（referrals）
- i18n `business-management.ts`：en/zh 同步新增/调整菜单文案（merge.ts 强制键对齐）。

### 5. 营销中心页面重写（`sdkwork-clawrouter-pc-admin-marketing` 包）
- `marketingService.ts`：新增 `createOffer/createStock/createCodeBatch` 调用 + 字段 normalize（snake_case→展示字段）；现有 list 函数字段映射对齐真实 DTO。
- **优惠券管理页（offers）**：列表 + 「创建优惠券」按钮 + 行操作（上架/下架 `offers.status.update`）。创建表单（抽屉，参照 memberships 包模式）：
  - 基本信息：名称、类型、受众、组合规则、商品范围、优先级、有效期、状态
  - 券面权益：金额券（面额 grantAmount + 折扣类型/折扣值/最低消费/最高抵扣/币种）| 订阅权益券（产品/SKU/套餐/周期/时长/日配额/总配额）
  - 发行设置：库存类型（有限/无限）、总量、每人限领、领取时间窗
  - **券码生成方式**：领取时实时生成（REALTIME，无附加项）| 按批次批量生成（BATCH，同表单展开批次参数：数量、码长、前缀、有效期，创建时联动建批次）
  - 提交链路：`offers.create` → `couponStocks.create`（带 code_issue_mode）→ BATCH 时 `codeBatches.create`
- **券码批次页（codeBatches，新页面）**：批次列表（批次号、类型、申请/生成数量、码长、前缀、状态）+「生成券码批次」按钮（选库存→填批次参数）；行操作「进入批次」→ `/admin/marketing/codeBatches/:batchId`。
- **批次券码页（batchId 详情）**：批次信息头 + 券码列表（`codes.list(codeBatchId=...)`，显示打码尾号、最大领取次数、已领数量、状态）+ 返回。
- **券码查询页（codes）**：统一查询（券码/code_no 模糊搜索 + 状态过滤），列字段对齐真实 DTO。
- **领取记录页（userCoupons）**：coupon_no、券码尾号、用户、状态、领取/生效/过期/核销时间、来源。
- **券码使用历史页（discountApplications）**：申请单号、订单号、优惠券、优惠金额、状态、申请/结算时间。
- **优惠券台账页（ledger）**：字段对齐重写。邀请分析（referrals）保持不动。
- 纯列表页继续使用 `AdminResourceCenter` sections（修正字段），offers/codeBatches 用自定义页面（参照 `sdkwork-clawrouter-pc-admin-memberships` 模板），新增 `pages/`、`forms/`、`components/` 目录。

### 6. 前端测试
- 新增 `marketing-runtime.test.ts`（沿用 `*-runtime.test.ts` 模式：node:test + fetch mock + SDK client 重置）：验证表单输入归一化（offer+stock+批次联动）、创建调用参数、列表字段映射。

## 验证

- sdkwork-promotion：`cargo test`（repository/claim 相关）、`pnpm sdk:check`、`pnpm api:assembly:validate`。
- clawrouter：`pnpm test`（相关 runtime 测试）、`pnpm check`、admin 包类型检查。
- 菜单/路由/权限：新页面挂在 `/admin/marketing` 前缀下，自动受 `clawrouter.admin.access` 权限保护，无需额外配置。

## 不做的事

- 不改 clawrouter 自有 OpenAPI 契约（promotions 属于外部 commerce 依赖契约路径，已由 `@sdkwork/promotion-backend-sdk` 暴露）。
- 不改用户端（app）领取页面 UI，只改后端领取发码逻辑。
- 不引入新组件库（沿用 Tailwind + commons 组件风格）。

## 风险点

- 池码发放并发安全：沿用现有 CAS/`FOR UPDATE` 守卫模式，池空时返回明确错误。
- 已存在生产数据：`code_issue_mode` 默认 'REALTIME' 保持存量 stock 行为不变。
- SDK 生成后 `marketingService.ts` 参数类型随之更新，需同步编译。
